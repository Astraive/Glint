- Repository infrastructure baseline (`[PRJ-001]`): governance and community files ([README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md), [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), [SECURITY.md](SECURITY.md), [SUPPORT.md](SUPPORT.md), [GOVERNANCE.md](GOVERNANCE.md), [VERSIONING.md](VERSIONING.md)), `.editorconfig`, `.gitattributes`, `.gitignore`.
- Opt-in local Git hooks ([.githooks/README.md](.githooks/README.md)) and read-only repository checks (`scripts/check-repository.py`, `scripts/check-conventions.py`, `scripts/check-powershell.ps1`) (`[PRJ-001]`).
- Repository operations guides ([docs/development.md](docs/development.md), [docs/issue-conventions.md](docs/issue-conventions.md), [docs/release-process.md](docs/release-process.md)) (`[PRJ-001]`).
- GitHub configuration, backlog validation and publication tooling, and their guides ([docs/github-setup.md](docs/github-setup.md), [docs/backlog-validation.md](docs/backlog-validation.md), [docs/backlog-publication.md](docs/backlog-publication.md)) (`[PRJ-001]`).
- `glint-schema` crate with a strict parser for the *proposed* `glint.json` v1 theme manifest, the proposed [JSON Schema](schemas/glint-theme-v1.schema.json) and a minimal valid fixture (`[SCH-001]`).
- Glint [threat model](docs/security/threat-model.md): trust boundaries, assets, actors, STRIDE per boundary and a hazard register with owner tickets, stop conditions and honest Implemented/Prototyped/Planned status; indexed in [docs/security/](docs/security/README.md) (`[SEC-001]`).
- Manifest version negotiation in `glint-schema`: `schemaVersion`, `compatibility.glint`, `compatibility.sdk` and `renderer.entrypointVersion` are compared independently and every failing axis is reported as `theme-incompatible` with a stable `GLINT_COMPAT_*` code; unknown fields stay rejected in security-sensitive sections and are ignored with a `GLINT_MANIFEST_WARN_UNKNOWN_FIELD` warning inside `author`; packages are never migrated. Specified in [docs/architecture/manifest-compatibility.md](docs/architecture/manifest-compatibility.md) (`[SCH-003]`).
- Shared manifest fixture corpus ([tests/package-fixtures/manifests/](tests/package-fixtures/README.md)) with golden expectations, and the `@glint/theme-schema` TypeScript package: types generated from the proposed JSON Schema with a CI drift check, and a validator that matches the Rust parser's verdict, error code and JSON Pointer on every fixture. CI gains a pinned Node job running the parity tests, type check and drift check (`[SCH-002]`).
- `glint-package` crate with `inspect_archive`: a strict, bounded `.glint` reader that identifies archives by magic bytes, copies them into Glint-owned private staging while hashing (SHA-256), rejects traversal, absolute, drive, UNC/device, symlink/hardlink, case-folded duplicate, oversized, over-deep and high-ratio entries before extraction, validates `glint.json` and its referenced files, and extracts into a read-only staging directory, with stable `GLINT_PACKAGE_*` error codes and a generated hostile-fixture suite (`[PKG-001]`).
- `glint-package` `pack_directory`: a deterministic `.glint` packer (sorted entries, fixed 1980-01-01 timestamps and `0644` modes, Deflate, no extra fields) that refuses symlinks, junctions, executables and invalid manifests, skips hidden files, `node_modules` and build-tool files, and returns the archive SHA-256; packing twice is byte-identical and pack → inspect → pack keeps the digest (`[PKG-003]`).
- `glint-platform` crate (no OS-specific dependency) with the capability vocabulary: validated namespaced `CapabilityId`, the five-state `Availability` (an unavailable capability always carries a typed reason), `Capability`, `IntegrationEffect`, and `CapabilityError` with stable kebab-case codes (`unsupported-platform` ... `invalid-state`, plus `permission-denied`, `read-only`, `unknown-capability`, `timeout`, `adapter-failure`), UI guidance and an error category; everything round-trips through JSON (`[CAP-001]`).
- `glint-platform` capability service: discovers capabilities through an adapter trait, keeps a generation-numbered snapshot and notifies subscribers of every availability transition (permission revoked, device removed, capability gone, adapter down); undiscovered, unadvertised and stale capabilities are never reported usable. A full-state mock adapter reaches every availability state and scripts live transitions and discovery timeouts/failures (`[CAP-002]`).
- Capability validation before activation in `glint-platform`: a theme manifest's unusable required capabilities (permission-gated, unavailable, not advertised, adapter down) refuse activation as `theme-incompatible` with every blocker listed, unless a declared fallback is usable; unusable optional capabilities only disable controls; the activation step runs only after the gate passes, so the current theme is kept. Threat-model rows B5.1, B5.6 and B9.9 updated to partly implemented (`[CAP-003]`).
- Package security fixture suite documented in [docs/security/package-fixtures.md](docs/security/package-fixtures.md) (every generated hostile fixture and its expected `GLINT_PACKAGE_*` code) and run as a named CI step on Linux, Windows and macOS (`[PKG-002]`).
- Windows system provider spike (`spikes/windows-system-providers`, throwaway): Core Audio endpoint volume, Network List Manager / WinRT network and battery providers mapped per sub-capability to supported / read-only / permission-required / unavailable, with restart, stale-subscription and COM apartment evidence in [docs/research/spikes/windows-system-providers.md](docs/research/spikes/windows-system-providers.md) (`[SPK-010]`).
- `glint-sources` crate: the `ThemeSource` model (registry, Git, local archive, local directory, artifact URL), a source-agnostic `PackageSource::stage` trait returning a `StagedPackage` with a `SourceOrigin` provenance record, and `LocalSource`, which stages local `.glint` archives through the strict reader and packs local directories deterministically before inspecting them, without ever running a build. Missing paths report `GLINT_SOURCE_NOT_FOUND`; registry, Git and artifact URL sources report `GLINT_SOURCE_UNSUPPORTED` until their M4 backends exist (`[SRC-001]`).
- `glint-sources` `parse_theme_source`: a pure, network-free parser for theme source strings (`registry/package[@version]`, `https://…/repo.git` or `git+https://…` with the *proposed* `#ref:subpath` fragment, `https://….glint` artifact URLs, and local paths starting with `/`, `./`, `../`, `~/` or a drive). It refuses `file:`, `http:`, `ssh:`, `git:`, `ext::`, `javascript:` and every other scheme, SSH shorthand, leading `-`, credentials in URLs, IP-literal and local hosts, UNC and device paths, control and invisible characters, dot segments and encoded separators, ambiguous forms and input over 2048 bytes, with stable `GLINT_SOURCE_URL_*` codes; accepted URLs are canonicalized (`[SRC-002]`).
- WebView2 rendering baseline spike (`spikes/webview2-baseline`): one React 19 panel bundle measured in WebView2 157 on the Windows host (system fonts, layout, 49 CSS feature probes, translucency, rAF frame timing, PNG/SVG/WebP/AVIF decode, UI Automation accessibility tree, process-tree memory), with a proposed portable CSS baseline and fallback pattern whose WebKitGTK and WKWebView rows stay UNVERIFIED until SPK-009; report in [docs/research/spikes/webview2-baseline.md](docs/research/spikes/webview2-baseline.md) (`[SPK-008]`).
- Proposed [ADR 0006](docs/adr/0006-package-identity-and-origin-collisions.md) on package identity and cross-origin collisions: (`kind`, `id`) keys bound to one canonical origin per installation, immutable versions per origin, hash-locked releases, explicit disambiguation for the same `id` from another origin, and the INS-004 test cases; `glint-schema` gains the matching pure `PackageKey`, `PackageOrigin`, `Sha256Digest`, `PackageRelease` and `classify_install` with stable `GLINT_IDENTITY_*` outcomes (`[SCH-004]`).
- Proposed `profile.json` v1 and `profile.lock` v1 formats ([profile format](docs/architecture/profile-format.md)): JSON Schemas under [schemas/](schemas/glint-profile-v1.schema.json), `glint-schema` parsers with stable `GLINT_PROFILE_*` codes, one theme version per profile, lock entries that must pin kind, id, exact version, canonical origin and SHA-256 digest, local-only flagging of private wallpaper files and machine-specific monitor keys for export, `verify_profile_lock`, and synthetic [profile fixtures](tests/profile-fixtures/README.md) (`[SCH-006]`).
- Proposed `config.toml` v1 application config and merge policy ([application config](docs/architecture/application-config.md)): read-only bundled defaults in [config/default.toml](config/default.toml), a [JSON Schema](schemas/glint-config-v1.schema.json), and `glint-schema` `parse_config_layer`/`resolve_config` with stable `GLINT_CONFIG_*` codes. User keys override defaults one by one and `[registries.<name>]` merge by name; user changes that weaken a security default are reported; settings requested by a package are never applied and are reported as ignored, so `allow_native_scripts`, `confirm_new_permissions` and `untrusted_network_default` cannot be weakened by a theme. Adds the `toml` crate (`[SCH-007]`).
- `glint` CLI skeleton: the *proposed* command tree (`doctor`, `status`, `safe-mode`, `theme ...`, `profile ...`, `registry ...`, `permissions list`) with argument checking, a schema-versioned `--json` envelope ([schemas/glint-cli-output-v1.schema.json](schemas/glint-cli-output-v1.schema.json)) and stable exit codes for usage, unsupported, invalid package, permission denied, missing daemon, not found and timeout; the interactive `glint theme` chooser is only offered on a terminal. `glint version` and `glint theme validate [PATH]` (package and manifest checks through `glint-sources`/`glint-package`) work; every other command fails with `GLINT_CLI_NOT_IMPLEMENTED` (exit 3) and never reports success. Documented in [docs/cli/reference.md](docs/cli/reference.md) (`[CLI-001]`).
- Bundled default theme [themes/default](themes/default/README.md) (`official.default`): a real `.glint` package with a v1 manifest that needs no capability, graphite and silver tokens, a static script-free panel surface, a preview image and the MIT licence, all repository-owned and offline; it packs deterministically and passes the same strict package reader as third-party themes (`cargo test -p glint-package --test default_theme`) (`[THM-001]`).
